# Mancermundo — agent orientation

Fan-made 3D browser game of Necromunda (2023 Rulebook edition + current House of Chains / House of Blades lists and FAQ, mechanics 1:1), MGSD figures, player vs AI. v1: skirmish battles (no campaign), Zone Mortalis board, Goliath vs Escher. Read in this order, nothing else up front: `HANDOFF.md` (current state, next steps) → `STATUS.md` (what exists) → `PLAN.md` (decisions, milestones) → `KICKOFF.md` (owner's answers and reasoning) → the `docs/spec/` sections a task names. Cross-project lessons live in `docs/knowledge-base/README.md`; read only the section a task needs.

Lineage: the code base started as a copy of the Kill Team sibling (`wh40k-murder-squad`, M7) on 2026-10-26. Its engine contract, client, AI framework, presentation director, dice tray, audio manager and tools carry over; the Kill Team rules modules, data and art are replaced.

## Owner priorities
- **Playable first.** Something the owner can open on Pages and play beats test coverage. Every stage ends in something visible (screenshot).
- **Fidelity is the product.** Mechanics 1:1 from the current edition (sources in `docs/sources/`, gitignored). Never tune printed numbers. Ambiguities never block: append `RULING: <rule> | <what we did> | <why> | <status>` to `docs/needs-rules-check.md` (status: Confirmed, Corrected, Unsourced, Fan-source) and keep going.
- **No intervention run.** Make the logical choice, record it in `PLAN.md` (decisions table) with its reasoning, and continue. Check-ins are 10 lines or fewer with a screenshot. Stop only for passwords, payment, account creation or a real blocker.

## Token rules (metered plan; not optional)
- The main loop never reads whole source files or hand-writes bulk code. It writes agent briefs with exact file lists, reads structured results and diffs, and runs the gates.
- Implementation and data entry run on Sonnet agents. Spec work and verification of rules-dense code (shooting/close combat sequence, injuries, weapon traits, gang data) run on the session model. Agents return ≤300-token summaries.
- One or two agents per milestone, one stage at a time, commit and push after each stage. Agents never run `npm install`, `git commit` or `git push` unless told; never edit `STATUS.md`, `package.json` or files outside their list; run long commands in the foreground with a time cap; never `taskkill` by image name.
- Gates: `npm run typecheck`, `npm test`, `npm run validate:data`, `npm run sim -- --games 50`, `npm run bench:ai`, one Playwright game.

## Conventions
- 1 world unit = 1 inch, y up, board centred at the origin (size per `docs/spec/10-rules-core.md` Zone Mortalis section); `+Z` is the figure's front.
- Engine contracts (`src/engine/{types,actions,events,hooks,rng,decider,view,index}.ts`) follow `docs/spec/00-architecture.md`; changes are additive and get a row in its change log.
- Exactly one `PendingDecision` at a time; `legalActions` is never empty for an open decision; illegal input returns a `Rejection`, never throws; deciders see only `view(state, seat)`; the engine owns every number the UI shows (`query.*`).
- Engine tests are named by checklist ID from `docs/spec/12-rules-test-checklist.md` (e.g. `it('SHOOT-004 ...')`).
- Data is declarative JSON validated by ajv; `{"code": "<hook>"}` escape hatches are registered in `src/engine/code-hooks.ts`, and every code hook has a test proving it fires in a real game.
- Client: `src/client/store/game.ts` is the only caller of `step`; presentation runs through the director and presented-state cursor; the bot waits for presentation idle; no native `title=` tooltips (shared `Tooltip.tsx`); prompts name what they decide and show engine odds.
- Figures: body GLB per fighter archetype with named sockets; weapons and wargear are attachment GLBs chosen by the fighter's loadout; procedural stand-in until the GLB exists. GLB contract: origin at base centre, y up, 1 unit = 1 inch, front `+Z`, pre-scaled upstream.
- Art: concepts from Gemini via Claude in Chrome (never Flux/SDXL substitutes for figures), 3D via Hunyuan3D on this PC only (not Alteisen). Zone Mortalis walls and floors stay procedural (image-to-3D cannot do flat terrain).
- Audio: generated by the local Audio Studio (http://localhost:7890) through `tools/gen-audio.ts` from `tools/audio-manifest.json`; weapon-flavour map first; measured trims; audition page `public/sounds.html`. No ElevenLabs.
- Commit messages: `M<n>: <what>` + blank line + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Pushing to `main` after each stage is pre-approved; Pages deploys from `main`.

## IP and privacy
Mechanics are ported 1:1; gang, fighter, weapon and skill names may match; all prose (rules text, lore, UI copy) is our own wording, never Games Workshop text. No GW art, icons or logos. `docs/sources/` (PDFs, extracted text, web dumps) is gitignored and never published. Figures are original MGSD designs. Credit the owner as **evilgouki**; never write the owner's real name or home path into any file; the pre-commit hook (`.git/hooks/pre-commit`) refuses both, and grep before every commit anyway.

## Edition leak list (paste into every rules prompt)
See `docs/knowledge-base/necromunda-rules-primer.md` §Edition leak list. In short: not 1995 Necromunda (IGOUGO gang turns, combat score), not Kill Team (APL, Engage/Conceal, defence dice, crit/tac ops), not 40k (unit coherency, CP, Leadership battle-shock). Inches only; alternating fighter activations; hit vs BS/WS, wound S vs T, save with AP, Injury dice.
