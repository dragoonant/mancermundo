## 4. Engine: what differs from Mallet
The Mallet contract (pure `step`, one `PendingDecision`, events, seeded RNG, replay, `view`) was kept; the module split came from Fell-in because Kill Team alternates single activations. Full detail: `docs/spec/00-architecture.md` in the Murder Squad checkout (Mancermundo's `docs/` has only `audio.md`, `needs-rules-check.md` and this knowledge base, so the specs must be copied from there).
- **Module namespace owners** (one owner per `<namespace>.<verb>` action kind): `setup`, `strategy`, `firefight` (activation order, Engage/Conceal, AP ledger, restrictions, counteract, Guard interrupts), `movement` (increments rounded up to 1", climb/drop/jump, control range), `shoot` (six steps), `fight` (assist, strike/block), `weapons` (every weapon rule as a hook), `markers`, `ploys`, `equipment`, `missions`, `abilities`, `teams/<id>.ts` (code hooks only). `query.ts` owns every displayed number (hit odds, expected damage, kill odds, cover/obscured verdict, control). Dependency direction `data <- engine <- ai <- client` enforced by `tests/engine/boundaries.test.ts` (it greps imports).
- **Decision kinds** (about 28): `setup.{initiative,dropZone,deploy,equipMarker}`, `strategy.{initiative,decideInitiative,gambit}`, `firefight.{activate,order,action}`, `move.path` (continuous, `legalActions` returns null), `shoot.{weapon,target,coverSave,block}`, `fight.{target,weapon,resolve}`, `dice.{reroll,commandReroll}`, `weapon.choice`, `ploy.firefight`, `guard.interrupt`, `ability.choice` (generic enumerated choice for team rules), `marker.place`, `confirm`. Ploy windows open only when the seat can actually use something (bounded AI decisions, snappy human play).
- **Defence choices are decisions with an `auto` option**: the defender allocates blocks, the engine offers `auto` (minimises damage taken); the AI uses it. Fight strike/block is fully interactive and a small minimax solves it (also powers the human `auto`).
- **Open information in Kill Team** is almost total: `view(state, seat)` hides only unrevealed equipment markers (Mines); even the Wyrmblade HIDING set-aside operatives are shown to both seats (RULING).
- **Geometry choices that held up:** visibility is a ray from the operative's head point (`pos + (0, height*0.9, 0)`) to sample points of the target silhouette (5 around the base at mid-height plus the top of the head, base excluded); operatives block visibility; doorway rule (a base may overlap the walls beside a door but its centre must go through the doorway); positions rounded to 1/1000 inch with a 0.005" tolerance on rounding up an increment. Oval bases = three discs of the short-axis radius along the long axis (within 0.07" of the ellipse) rather than exact ellipse maths.
- **Performance budgets written down:** step p50 < 0.5 ms, `legalActions` < 5 ms, sim >= 5 games/s, AI p50 < 50 ms, JS <= 2.5 MB gz, `GameState` JSON < 150 KB. (At 24 teams the sim fell to about 4.5 minutes per 40 games; AI move planning is the hot path. No fix recorded.)
- **Post-M7: the team-extension mechanism** (not in the Mallet entry; the biggest reusable idea of the project). After the first two teams, 22 more teams were added by batches of 4 to 7 using this recipe:
  1. A per-team spec section in `13-teams.md` written first, including a **generic-capabilities survey** (what the team needs that no shared file offers), gotchas, an engine map and an implementer brief.
  2. **One engine-prep stage per batch** adds the generic capabilities (team rule providers in `team-rules.ts`, tokens, pools, reserve/set-aside, free/delegated/forced actions, joint activations, lifecycle hooks, per-action `maxRepeats`, new ploy/timing windows) and creates scaffold teams behind `playable: false` in `team.json`.
  3. Then parallel implementers each own one team's files (`src/data/teams/<team>/`, `src/engine/teams/<team>.ts`, `src/client/teams/<team>.ts`, `tests/engine/teams/<team>.hooks.ts`) and flip `playable` when done. Shared files never name a team again (PLAN decision "Team extension"): code-hook list is derived from data at load (no generated shared file to conflict), presentation tables merge per-team files, `ploy-rules.ts` and `point-handlers.ts` are leaf modules (type-only imports) because the `abilities -> teams` import cycle caused TDZ errors.
  4. A verification pass reads each team line by line against the sources, then a follow-up pass turns stopgap rules into exact ones via new windows. Sim and bench rotate every playable team (`--teams real`: each team at least floor(2G/n) times; `bench:ai` team `g mod n`; `--pair a,b` for one pairing).
  5. New timings were added as windows/hooks rather than team branches (declaration veto, opponent declaration, end-of-activation reactions, pre-activation, opponent-ploy nested window, kill window, fresh-roll windows). Removals outside attacks that some rule may answer are deferred to a queue at the end of the step (`pausableRemoval`), because `inflict` itself stays synchronous.
- **Per-team firing test:** every `{"code": ...}` hook needs a scenario proving it fires in a real game (`code-hooks.test.ts` merges per-team scenarios).

## 5. AI
Spec `docs/spec/40-ai.md`, code `src/ai/{decider,tiers,eval,threat,moves,nav,shoot,fight,ploys,setup,random,worker}.ts` plus post-M7 `teamActions.ts`, `choices.ts`. Tiers random / easy (noise, random among top 3) / normal (one-activation lookahead for shoot/charge outcomes, tac-aware objective play). Method: threat map (sum over enemy ready operatives of expected damage next activation, concealed-in-cover = untargetable), activation planner over sampled end points (order x move target x action list within APL scored `damageDealt - damageTakenRisk + objectiveDelta + positional`), exact numbers from `engine.query.expectedDamage`/`killOdds`/`fightOutcome` and never re-derived, Web Worker host with 3 s timeout and random fallback.
- Result: normal 4.7 ms per decision, 0.2% zero-action activations, bench 40-0 vs random. Bench gates in the spec: normal >= 95% vs random, normal >= easy, mean decision < 50 ms, zero rejections/stalls/fallbacks, zero-action activations < 2%.
- **Bench caveat recorded:** equal-skill matches sat near 50% because Angels of Death beat Kommandos regardless of seat, so the bench also reports VP difference. At ten teams zero-action activations sat near the 2% gate; re-measure at 24 was listed as open.
- Post-M7 AI work: oval-base facing at the end of a move (give up an inch or two of the last leg only when the shorter end point scores no worse), HIDING picks, FLY set-ups, mine placement, team action and choice handlers.
- Not done: tac-op scoring, grenades, most unique actions, hard tier, multi-turn lookahead.

## 11. What didn't, and rework it cost
- **The figure approach changed after a day** (section 7): modular bare-handed bodies + attachments (owner asked for WYSIWYG loadouts) to weapons-fused dynamic poses. Lock the pose and weapon strategy before the first batch.
- **Skeletal animation** was planned as a milestone and dropped after a pilot.
- **Invented terrain layouts and generic-GLB buildings** were replaced by the official cards and by rules-geometry drawing after owner reports.
- **Off-model concepts** passed a vague "check each image" gate.
- **Regeneration slip:** a failed shape stage was masked by a stale `outputs/<slug>/shape.glb` being re-painted; two teams' bodies (Legionaries, Hand of the Archon) were committed and then reverted within a minute (22:33 on 10-18) and redone after `run_v2_local.bat` was changed to clear stale meshes. The shape log must show `shape done` per slug before a batch is trusted.
- **Sim cost grew with content** (4.5 min per 40 games at 24 teams) and nobody profiled it.
- **Docs went stale again** (STATUS/HANDOFF still describe batches C and D as stand-ins one day after the figures landed); local `main` lagged `origin/main` by 70 commits.
- **Rules sourcing:** about two thirds of the 1164 RULINGs are Unsourced; Approved Ops tac-op card text was never found; some rules wait on a resumable damage pipeline (Medic! inside attacks, Flay timing and others listed in HANDOFF).
- **Privacy slip:** one early commit (`ae22229`, a batch script) carried a machine path; scrubbed next commit, history left alone (owner's call). The `.git/hooks/pre-commit` privacy check (patterns in `privacy-patterns.txt`) works only in the main checkout: in a worktree `.git` is a file, the pattern file is not found and the check passes silently. ## 13. Gotchas (new in this project)
- Bash heredocs mangle backslashes in this shell: write `.bat` files and Windows-path JSON with the Write tool.
- `stage_shape.py` lives in the Hunyuan 2.1 folder and must run with that cwd; `stage_finalize.py` lives in the 2.0 folder and hard-codes `units.json` (use `merge_units.py`).
- Long remote jobs: launch detached with `schtasks`, never over an attached ssh (10-minute tool cap); never `taskkill` by image name (refused by policy anyway). Parallel subagents leave orphaned wait-loop shells: one wait per tool call, never chain polling loops across agents.
- Hunyuan 2.1 shape stage needs about 40 GB of Windows commit charge (GPU allocations count against it): free memory first and keep the pagefile large. The owner's rule: stop the local studio services when a session is done with them, and the main PC may run Hunyuan batches only after they are stopped and commit charge is checked; Alteisen stays the default queue. Alteisen's C: drive was nearly full (TEMP redirected to E:): check free space on both drives before a batch. Alteisen was unreachable at one point and the art run waited on the owner powering it on.
- The feet-based facing vote in `measure-sockets.py` is unreliable on dynamic poses (ignore the `?`).
- `registerPloyRule` must be imported from the leaf `ploy-rules.ts` in team code (import-cycle TDZ).
- Free actions take an opt-in `checkPerformed` (default off): turning the once-per-activation check on by default broke eight teams' free actions.
- Per-TP use ledgers must be cleared at every turning point start, not only keys with a `limit:` (batch B fix; once-per-TP items were working once per battle).
- The data schema must not accept fields the engine never interprets (`modifyStat` accepted `apl`, `save`, `wounds` that did nothing).
- Ploy windows open only when the seat can actually use something; a window must offer nothing and change no state when no ploy names it (keeps AI decisions bounded and human play snappy).
